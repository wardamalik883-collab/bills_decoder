# Plan: Utility Bill Decoder (WTQ Build Track)

> Single source of truth for the project. If you get stuck, re-read sections 1, 5 and 8, then open `task.md` and continue from the first unchecked task.

## 1. Goal

Build an AI assistant that reads a Pakistani electricity bill image (K-Electric, LESCO, IESCO) and:

- **Level 1:** returns one JSON object per bill (fixed schema, guide section 5).
- **Level 2:** answers 12 customer questions per bill in plain English (guide section 6).

Final output: `output/level1.csv` (10 rows), `output/level2.csv` (120 rows), plus source code, README, `.env.example`, optional demo video, all in one ZIP (max 15 MB), submitted **once** before **1:30 PM**.

## 2. Scoring (what we optimise for)

| Area | Pts | What it means for us |
|---|---|---|
| Extraction accuracy | 30 | Exact text/dates, numbers within +-1, correct `null`s, no invented values |
| Answer quality | 30 | Correct numbers, grounded in bill, estimates labelled, "not on bill" stated clearly |
| Engineering quality | 15 | Clean modules, error handling, retries, no crashes |
| AI design | 15 | LLM used where it adds value; calculations done in code |
| Completeness / reproducibility | 10 | One command runs everything; README is accurate |
| Demo (bonus) | +5 | <= 3 min screen recording |

## 3. Hard constraints (never violate)

1. Only these LLMs: Claude Haiku 4.5, Gemini 3.5 Flash-Lite, Gemini 3.1 Flash-Lite, GPT-4.1 mini, GPT-5 mini. Anything else = disqualification.
2. No invoice-extraction services (Azure prebuilt-invoice, Textract AnalyzeExpense, Mindee). Local OCR (Tesseract, PaddleOCR) is allowed.
3. CSVs must be generated by code, never hand-edited.
4. No API keys or `.env` in the ZIP.
5. Python 3.11+ (we use Python), `requirements.txt` with exact versions.
6. No personal identifiers in outputs (name, address, CNIC, account/reference/consumer/meter numbers).
7. Only one submission is allowed. Open the ZIP and verify before uploading.

## 5. Architecture

```
bills/*.png|jpg
   |
   v
[preprocess]  (optional: auto-rotate, resize, contrast)
   |
   v
[Extractor: vision LLM + strict JSON schema]  --> raw Level-1 JSON
   |
   v
[Validator (code)]  schema types, sign rules, sum checks, null rules
   |   \__ on failure: retry LLM once with the error message
   v
Level-1 JSON  --------------------------> level1.csv
   |
   v
[Context extractor: usage history, billing history, tax split %, message board]
   |
   v
[Q&A: LLM + calc tools (python)]  --> answers (English, estimates labelled)
   |
   v
level2.csv
```

Design decisions:

- **Vision LLM first**, not OCR. Handles tilted and Urdu bills better. Tesseract only as optional fallback, only if time permits.
- **Provider abstraction** (`MODEL_PROVIDER`, `MODEL_NAME`, `API_KEY`) so we can switch between Gemini, Claude, OpenAI in one line if a rate limit hits.
- **Structured output / strict JSON** validated with pydantic.
- **Math in code**: percentages, averages, counts, differences are computed in Python and given to the LLM as facts.
- **Cache** every LLM result on disk (`cache/`) so reruns do not waste requests or time.
- **Fewer requests**: one Q&A call per bill containing all 12 questions (Gemini free tier = 15 req/min, 500 req/day).
- **Fail-soft**: one bad bill must never stop the run. Fall back to `null` fields / "information not available" answers rather than empty cells.

## 8. If you get stuck (decision rules)

- **Stuck > 15 minutes on one bug:** write down what fails, skip to the next task, come back later.
- **Rate limit (429):** add exponential backoff; if it continues, switch `MODEL_PROVIDER` / `MODEL_NAME`.
- **Model gives wrong numbers on a field:** improve the prompt for that field, add an example from KESC_0008, add a validator check.
- **Field unreadable:** return `null` (a correct null scores as correct). Never guess.
- **Running out of time:** priority order is (1) valid CSVs with all rows filled, (2) Level 1 accuracy, (3) Level 2 quality, (4) README and packaging, (5) demo.
- **Never** leave an empty `json` or `answer` cell. Use a safe fallback instead.

## 9. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Free Gemini quota exhausted | Cache results, batch Q&A per bill, keep a second provider configured |
| Bills tilted / Urdu / low quality | Prompt says "read Urdu, answer in English"; optional rotation preprocessing |
| Wrong sign on credits (CR) | Explicit rule in prompt + validator check |
| Model returns invalid JSON | Structured output + pydantic + one retry |
| Wrong charge/tax classification | Classify by printed **section**, include type tables in prompt |
| CSV quoting errors | Use `csv` module only, never manual string joins |
| Secrets leaked in ZIP | `.gitignore` + final checklist step (T15) |
| Run takes too long on test day | Concurrency of 2-3 workers max, caching, dry run on training bills in T12 |
